# 0008. 로그인은 Supabase Auth의 구글 로그인 하나로 붙이고, 로그인하면 "나" ID만 계정 ID로 바꾼다

- 상태: 결정
- 날짜: 2026-10-28

## 맥락

즐겨찾기, 내 기록, 계정 닉네임 같은 개인화 기능을 만들려면 기기를 바꿔도 같은 사람으로 알아봐야 한다. 지금은 브라우저 쿠키(`lm_voter`) 하나를 한 사람으로 보므로, 쿠키를 지우거나 기기를 바꾸면 평가·키워드·팀원 자격을 잃는다(ADR 0003). 한편 이 지도는 "로그인 없이 링크만 있으면 누구나"가 원칙이고, 개인정보는 가능한 한 적게 받고 싶다.

## 결정

- **Supabase Auth의 구글 로그인 하나만** 붙인다. DB가 이미 Supabase라 새 서비스가 필요 없고, 비밀번호·메일 발송을 만들지 않는다.
- 로그인 흐름(`/auth/login` → 구글 → `/auth/callback`)과 세션 확인은 모두 서버에서 돈다. 세션은 Supabase의 `sb-…` 쿠키에 두고 `@supabase/ssr`로 읽는다. 브라우저에서 Supabase를 부르지 않으므로 브라우저용 키를 따로 두지 않고 기존 서버 키를 쓴다.
- **"나" ID 하나로 사람을 구분한다.** 로그인했으면 `u:<auth.users id>`, 아니면 지금처럼 브라우저 ID다. 평가·키워드·노점 확인·팀원·조장·추첨통에 넣은 가게·즐겨찾기·꿀팁 쓴 사람이 모두 이 ID를 담는다. 칸의 모양이 그대로라 기존 테이블과 추첨 코드를 바꾸지 않는다. 쿠키로 계정인 척하지 못하게 쿠키 값은 우리가 발급한 UUID 모양만 받는다.
- 로그인할 때마다 그 브라우저에 쌓인 기록을 계정으로 옮긴다(`claim_browser`). 같은 가게·노점·팀에 둘 다 기록이 있으면 계정 것을 남긴다.
- 로그인하지 않아도 지금 기능과 즐겨찾기·내 기록을 모두 쓸 수 있다. 로그인은 "기기를 바꿔도 이어지게" 하는 것이다.
- **개인정보 최소 수집**
  - 구글에는 Supabase가 기본으로 요청하는 범위(이메일·기본 프로필)만 요청하고 더 넓히지 않는다. Supabase는 이 범위를 줄이는 설정이 없다.
  - Supabase는 `auth.users`에 이메일과 구글이 넘겨준 이름·사진 주소를 저장한다. 우리 코드는 이것을 읽지 않고, 우리 테이블에는 계정 ID와 사용자가 직접 정한 닉네임(`profiles`)만 둔다. API도 로그인 여부와 닉네임만 내보낸다.
  - 꿀팁의 쓴 사람(`tips.author_id`)은 내 꿀팁 모아보기에만 쓰고 꿀팁 API에는 넣지 않는다.

## 고려한 대안

- **카카오 로그인**: 국내 사용자에게 더 익숙하지만 앱 설정 단계가 많고, 이메일 동의 항목 설정에 따라 비즈 앱 전환이 필요할 수 있다. 같은 Supabase Auth 위에 나중에 버튼만 더할 수 있다.
- **이메일 매직 링크**: 버튼은 쉽지만 Supabase 기본 메일 발송 한도가 매우 낮아 메일 발송 서비스를 따로 붙여야 한다.
- **아이디·비밀번호**: 비밀번호 저장과 찾기를 직접 책임져야 해서 기각.
- **계정 전용 칸(user_id uuid)을 새로 두고 기존 칸과 나란히 쓰기**: 평가·팀원 같은 모든 테이블과 쿼리가 두 갈래가 된다. 한 칸에 "나" ID를 담는 쪽이 바꿀 곳이 훨씬 적다.
- **처음 로그인할 때만 옮기기**: 로그인한 브라우저에서 로그아웃 뒤 남긴 기록이 다음 로그인 때 옮겨지지 않는다. 매번 옮겨도 같은 기록을 두 번 옮기는 일은 없다.

## 결과

- ADR 0003의 "조장이 쿠키를 잃으면 추첨을 못 한다"는 로그인한 조장에게는 더 이상 생기지 않는다. 로그인하지 않은 조장에게는 그대로다.
- 옮길 때 계정 것을 남기므로, 두 기기에서 같은 가게에 다른 평가를 했다면 브라우저 쪽 평가는 사라진다. 두 쪽 모두 같은 팀의 추첨통에 가게를 넣었다면 계정의 넣은 횟수가 한도를 넘을 수 있다.
- 이 칸이 생기기 전에 쓴 꿀팁은 누가 썼는지 모르므로 내 꿀팁에 나오지 않는다.
- 회원 탈퇴는 아직 없다. Supabase에서 계정을 지우면 `profiles`는 같이 지워지지만, 평가·꿀팁 등에 남은 `u:` ID는 남는다(누구인지 알 수 없는 ID가 된다).
- 운영하려면 Google Cloud OAuth 클라이언트와 Supabase(개발·운영 각각)의 Google provider, Redirect URLs 설정이 필요하다(README 「로그인 설정」).
