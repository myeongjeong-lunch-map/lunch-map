# 점심 코스 설계 (가게 + 산책)

점심시간(12:50~14:00, 70분) 안에 **밥 먹고 산책하고 14시 전에 자리로 돌아오는** 조합을 보여 준다.
가게에서 먹고 걷는 **먹고 걷기**와, 포장해서 산책 장소에서 먹는 **포장해서 먹기** 두 가지다.

- 요청: "1시간 10분을 넘는 산책 코스는 의미가 없다", "식당과 엮은 코스를 보여 주면 좋겠다", "서리풀공원이나 예술의전당으로 포장해서 먹는 코스도", "이미 있는 거리 값을 조합해서 호출을 아끼자"
- 상태: 설계 초안 (2026-10-23). 코드는 아직 없다.
- 기준 코드: PR #5(컴포넌트 폴더 정리)와 PR #6(구조 개선)이 머지된 `master`. 파일 경로는 PR #6 기준이다. 둘이 머지되기 전이면 먼저 머지를 기다린다.
- 구현자: 이 문서만 보고 따라갈 수 있게 썼다. 끝의 [사용자에게 확인할 질문](#사용자에게-확인할-질문)은 추천안대로 구현하고, 답이 다르면 그때 고친다.
- 관련 결정: [ADR 0001](../adr/0001-walking-time-daily-refresh.md)(도보 시간 매일 재계산), [ADR 0005](../adr/0005-walk-course-time-from-daily-legs.md)(코스 시간은 구간을 더한다), [walk-routes.md](walk-routes.md)(산책 코스)

## 한눈에

| 항목 | 결정 |
|---|---|
| 점심시간 | **12:50~14:00 고정, 70분**. 모든 계산이 "14:00 전에 캠퍼스 도착"을 기준으로 한다 |
| 먹고 걷기 | 자리에서 일어나 가게를 나설 때까지 **40분**(가게까지 걷기 포함). 남은 **30분** 안에 가게 → 산책 장소 → 캠퍼스 |
| 포장해서 먹기 | 캠퍼스 → 가게(포장 대기) → 산책 장소(먹기 20분) → 캠퍼스가 **70분** 안 |
| 점심 코스 모양 | 가게 1곳 + 산책 장소 1곳. 장소 여러 곳은 만들지 않는다 |
| 가게 → 산책 장소 시간 | 이미 있는 **캠퍼스↔가게**, **캠퍼스↔산책 장소** 값으로 범위를 구해 거른다. **최소치로라도 들어올 수 있는 쌍(화면에 나올 수 있는 쌍)은 모두** TMAP으로 매일 계산해 저장한다 (지금 데이터로 46쌍). 나머지 80쌍은 부르지 않는다 |
| 화면 | 🚶 산책 탭 맨 위에 **🍱 점심 코스**. 가게 카드(🎲 결과 포함)와 추첨 결과에 그 가게의 점심 코스. 셋 다 같은 컴포넌트 |
| 시간 표시 | 분보다 **복귀 시각**("13:52 복귀")을 크게 |
| 추천 코스 | 30분·45분 칩을 없애고 "점심시간에 다녀오기" / "여유 있는 날" 두 묶음으로 나눈다 |
| 데이터 정리 | 서리풀공원 지점을 공원 초입으로 옮긴다. 산책 장소에 "포장해서 먹을 수 있음", 가게에 "미리 주문" 표시를 더한다 |
| 팀별 노출 | 만들지 않는다 (YAGNI). 모두에게 보이고, 필요해지면 컴포넌트 하나를 팀 설정 뒤로 옮긴다 |

## 1. 왜 이렇게 하나

운영 데이터(2026-10-23)로 계산하면 지금 추천 코스 4개는 이렇다.

| 추천 코스 | 코스 시간 | 식사 40분을 더하면 |
|---|---|---|
| 예술의전당 한 바퀴 | 26분 | 66분 ✅ |
| 국악원 지나 예술의전당 | 41분 | 81분 ❌ |
| 서리풀공원 숲길 | 48분 | 88분 ❌ |
| 누에다리 넘어 몽마르뜨공원 | 89분 | 129분 ❌ (산책만으로 70분 초과) |

원인은 코스 시간을 **산책만 떼어서** 재고, 점심시간이 고정이라는 사실이 설계에 없었기 때문이다. 사람들이 실제로 하는 일은 "70분 안에 밥 먹고, 걷고, 14시에 돌아오기"이므로 계산 단위를 **점심시간 전체**로 바꾼다.

가게는 모두 캠퍼스에서 편도 7분 안에 있고, 산책 장소는 8~23분이다. 가게를 산책 방향에서 고르면 몇 분을 아낀다. 식후 30분에서는 그 몇 분이 승부를 가른다. 예를 들어 백년옥은 예술의전당 바로 옆이라, 캠퍼스에서 출발하는 26분이 식후 19분으로 줄어든다.

서리풀공원은 지점이 공원 한가운데라 캠퍼스에서 21분이었다. 공원 초입(명달로 끝)은 TMAP으로 12.8분, 맥도날드 서초GS점에서는 9.6분이다(2026-10-23 측정). 초입으로 옮기면 맥도날드 포장 코스가 약 48분(13:38 복귀)이 된다.

## 2. 용어

GLOSSARY.md에 아래를 더한다. 기존 **도보 시간**(캠퍼스 → 가게)과 **구간**(캠퍼스·산책 장소끼리)의 뜻은 넓히지 않는다.

```markdown
**점심시간 (Lunch Hour)**:
명정 캠퍼스의 점심시간. 12:50부터 14:00까지 70분으로 고정이다. 점심 코스는 14:00 전에 캠퍼스로 돌아오는 것만 보여 준다.

**점심 코스 (Lunch Course)**:
가게 한 곳과 산책 장소 한 곳을 묶어 점심시간 안에 다녀오는 길. 캠퍼스 → 가게 → 산책 장소 → 캠퍼스 순서다. 두 가지가 있다.
- **먹고 걷기**: 가게에서 먹고 산책 장소에 들렀다 돌아온다.
- **포장해서 먹기**: 가게에서 포장해 산책 장소에서 먹고 돌아온다. 포장해서 먹을 수 있는 산책 장소만 쓴다.
저장하지 않고 화면에서 그때그때 계산한다.
_Avoid_: 점심 루트, 식후 코스, 산책 코스 (산책 코스는 캠퍼스 → 산책 장소들 → 캠퍼스)

**가게 구간 (Place Leg)**:
점심 코스에서 가게와 산책 장소 사이를 걷는 길 하나. 이미 아는 캠퍼스↔가게, 캠퍼스↔산책 장소 시간으로 범위를 구하고, 범위만으로 판정할 수 없을 때만 TMAP으로 계산한다.

**복귀 시각 (Return Time)**:
점심 코스대로 다녀왔을 때 캠퍼스에 도착하는 예상 시각. 점심 코스 카드에 크게 보이는 값이다.
_Avoid_: 도착 시간, 귀가 시간

**미리 주문 (Pre-order)**:
가게 앱(예: 맥오더)으로 미리 주문해 두고 가서 받기만 하는 가게. 포장해서 먹기에서 기다리는 시간을 짧게 잡는다. 관리자가 표시한다.
```

## 3. 시간 계산

### 3-1. 상수 (`src/lib/domain.ts`)

```ts
// 점심 코스 (GLOSSARY.md: 점심시간, 점심 코스, 가게 구간, 복귀 시각, 미리 주문)
export const LUNCH_START = { h: 12, m: 50 };
export const LUNCH_MINUTES = 70;          // 12:50 ~ 14:00
export const DINE_IN_MINUTES = 40;        // 먹고 걷기: 자리에서 일어나 가게를 나설 때까지 (가게까지 걷기 포함)
export const TAKEOUT_WAIT_MINUTES = 10;   // 포장 대기
export const PREORDER_WAIT_MINUTES = 2;   // 미리 주문한 가게에서 받기
export const PICNIC_EAT_MINUTES = 20;     // 산책 장소에서 먹기
```

숫자는 모두 사용자가 확인한 값이다(2026-10-23). 실제로 다녀와 보고 다르면 이 상수만 고친다.

### 3-2. 두 가지 식

`c→p` = 캠퍼스 → 가게(`places.walking_seconds`), `c→s` = 캠퍼스 → 산책 장소(`walk_legs`, `spot_a = null`), `p→s` = 가게 구간.

| | 식 | 조건 |
|---|---|---|
| 먹고 걷기 | `40 + p→s + 둘러보기 + s→c` | ≤ 70 (식후 30분) |
| 포장해서 먹기 | `c→p + 대기(10 또는 2) + p→s + 먹기 20 + s→c` | ≤ 70 |

- 먹고 걷기의 둘러보기는 산책 장소 기본값 `walk_spots.stay_minutes`를 쓴다.
- 포장해서 먹기에서는 먹는 20분이 둘러보기를 대신한다. 둘을 더하지 않는다.
- 먹고 걷기에서는 `c→p`를 따로 더하지 않는다. 40분 안에 들어 있다.
- 분은 걷는 초를 모두 더한 뒤 한 번만 반올림한다(`courseTime`과 같은 방식).

### 3-3. 가게 구간: 범위로 거르고, 남은 쌍은 모두 TMAP

가게 구간은 캠퍼스를 거쳐 가는 길보다 길 수 없고, 두 값의 차이보다 짧을 수 없다.

```
최대치 = c→p + c→s           (가게 → 캠퍼스 → 장소로 돌아가는 길)
최소치 = |c→s − c→p|
```

**계산할 쌍 고르기 (크론):** 가게 구간에 **최소치**를 넣어 두 방식 중 하나라도 들어오면 TMAP으로 계산해 저장한다. 최소치로도 넘치는 쌍은 어떤 경우에도 화면에 나올 수 없으므로 부르지 않는다.

**판정과 보여 주는 값 (화면):**
1. **저장된 TMAP 값**(`walk_place_legs`, 24시간 안)이 있으면 그 값으로 판정하고, 그 시간과 경로선을 보여 준다. 평소에는 화면에 나오는 점심 코스가 모두 여기에 해당한다.
2. 없을 때는 크론이 아직 그 쌍을 계산하지 않은 경우다. 배포 직후, 또는 그날 새로 추가한 가게가 여기에 해당한다. 이때는 **최대치로 넣어도 들어오는 쌍만** 보여 준다.
   - 시간은 `estimateWalk`(직선거리 × 1.3을 시속 4km로 걸은 값)를 최소치~최대치 사이로 잘라 쓰고 "약"을 붙인다.
   - 가게 구간 선은 점선 직선으로 그린다.
3. 그 밖에는 보여 주지 않는다.

어림값으로 "된다"를 만들지 않는다. 2번은 최대치로 판정하므로, 실제보다 늦게 잡을 수는 있어도 14:00을 넘는 코스를 보여 주지는 않는다.

지금 데이터(가게 21곳 × 산책 장소 6곳, 서리풀공원은 초입으로 옮긴 값)로 세면 다음과 같다.
- **최소치로 통과 → TMAP 계산:** **46쌍** (그중 13쌍은 최대치로도 통과)
- **최소치로도 넘침 → 부르지 않음:** 80쌍
- 산책 구간 21건, 가게 21건과 합쳐 하루 약 90건이다. 무료 한도는 하루 1,000건이다. 가게가 늘어도 최소치를 통과하는 건 산책 장소 근처 가게뿐이라 가게 수만큼 늘지는 않는다.

### 3-4. 순수 함수 (`src/lib/domain.ts`)

```ts
export type LunchMode = "dine" | "takeout";
export type PlaceLeg = { place_id: string; spot_id: string; seconds: number; meters: number; source: "tmap" };

export type LunchCourse = {
  mode: LunchMode;
  place: Place;
  spot: WalkSpot;
  /** 캠퍼스 → 가게, 가게 → 장소, 장소 → 캠퍼스. 가게 구간이 어림값이면 rough */
  legs: { seconds: number; meters: number; rough: boolean }[];
  /** 출발부터 캠퍼스 도착까지 분 */
  totalMinutes: number;
  /** "13:52" */
  returnAt: string;
  rough: boolean;
};

/** 판정을 통과한 점심 코스만. 복귀 시각이 이른 순 */
export function lunchCourses(
  mode: LunchMode,
  places: Place[],
  spots: WalkSpot[],
  legs: Map<string, WalkLeg>,
  placeLegs: Map<string, PlaceLeg>,   // key: `${place_id}|${spot_id}`
  startAt?: Date,                     // 3-5
): LunchCourse[];
```

- 포장해서 먹기는 `spot.picnic`이 참인 장소만, 그리고 [4-3](#4-3-포장-가능한-가게)의 포장 가능한 가게만 쓴다.
- `walking_seconds`가 없는 가게, `c→s`가 없는 장소는 건너뛴다.
- 테스트할 값은 [7. 확인 방법](#7-확인-방법)의 표.

### 3-5. 복귀 시각의 기준

- 지금이 12:50 전이거나 14:00 뒤면 **12:50 출발** 기준으로 계산한다. 카드 제목은 "12:50에 나가면".
- 지금이 12:50~14:00 사이면:
  - **포장해서 먹기**는 지금 출발 기준으로 다시 계산한다. 카드 제목은 "지금 나가면". 14:00을 넘는 코스는 빠진다.
  - **먹고 걷기**는 12:50 기준 그대로 둔다. 이미 먹는 중일 수 있어서 출발 시각을 알 수 없다.
- 시각은 한국 시간(`Asia/Seoul`)으로 계산한다. 서버가 아니라 브라우저에서 계산한다.
- 1분마다 다시 그릴 필요는 없다. 탭을 열 때와 카드를 열 때 계산한다.

## 4. 데이터

### 4-1. 마이그레이션 (`supabase/migrations/` 다음 번호)

```sql
-- 점심 코스 (GLOSSARY.md: 점심 코스, 가게 구간, 미리 주문, docs/design/lunch-walk.md)

-- 1) 산책 장소: 포장해서 먹을 수 있는 곳 (벤치·광장이 있고 음식을 먹어도 되는 곳)
alter table public.walk_spots add column if not exists picnic boolean not null default false;

-- 2) 가게: 앱으로 미리 주문해 두고 받기만 하는 곳 (관리자가 표시)
alter table public.places add column if not exists preorder boolean not null default false;

-- 3) 가게 구간: 최소치로라도 점심 코스에 들어올 수 있는 가게 ↔ 산책 장소 쌍만. TMAP 약관에 따라 매일 다시 계산해 덮어쓴다 (docs/adr/0001)
--    path는 가게 → 산책 장소 방향 [경도, 위도] 배열
create table if not exists public.walk_place_legs (
  place_id uuid not null references public.places(id) on delete cascade,
  spot_id uuid not null references public.walk_spots(id) on delete cascade,
  seconds integer not null check (seconds >= 0),
  meters integer not null check (meters >= 0),
  path jsonb,
  updated_at timestamptz not null default now(),
  primary key (place_id, spot_id)
);
alter table public.walk_place_legs enable row level security;
grant select, insert, update, delete on public.walk_place_legs to service_role;

-- 4) 서리풀공원 지점을 공원 초입(명달로 끝)으로. 좌표는 2026-10-23 지도 그림에서 읽은 임시 값. 현장 답사 뒤 고친다 (남은 것 1)
update public.walk_spots set lat = 37.48835, lng = 127.00420, summary = '명달로 끝 초입. 숲길이 방배·서초역 방향으로 길게 이어진다'
where name = '서리풀공원';

-- 5) 포장해서 먹을 수 있는 산책 장소 (2026-10-23 사용자 확인)
update public.walk_spots set picnic = true where name in ('예술의전당', '서리풀공원');

-- 6) 미리 주문 가게
update public.places set preorder = true where name = '맥도날드 서초GS점';
```

- `walk_place_legs`에는 TMAP으로 받은 값만 넣는다. TMAP이 실패하면 저장하지 않는다. 어림값은 화면에서 계산한다.
- 서리풀공원 좌표를 바꾸면 그 장소의 `walk_legs`가 낡은 값이 된다. 배포 직후 `/api/cron/walk-legs`를 한 번 수동으로 돌린다([6. 배포 순서](#6-배포-순서)).

### 4-2. 서버 (`src/lib/server/walkingStore.ts`)

`refreshLegs` 옆에 하나를 더한다.

```ts
/** 최소치로라도 점심 코스에 들어올 수 있는 가게 ↔ 산책 장소 쌍을 모두 TMAP으로 다시 계산해 저장하고, 최소치로도 넘치게 된 쌍은 지운다 (매일 한 번). */
export async function refreshPlaceLegs(provider: RouteProvider = tmapProvider): Promise<RefreshReport>;

/** 24시간 안의 가게 구간(경로 좌표 제외) */
export async function readPlaceLegs(): Promise<PlaceLeg[]>;

/** 가게 → 산책 장소 경로 좌표. 없거나 낡았으면 null */
export async function readPlaceLegPath(placeId: string, spotId: string): Promise<WalkingPath | null>;
```

- 계산할 쌍을 고르는 기준은 화면의 판정과 같은 식을 써야 한다. `domain.ts`에 `placeLegBounds(c→p, c→s)`와 `lunchFits(mode, …, placeLegMinutes)`를 두고 서버와 화면이 함께 쓴다. 서버는 `lunchFits(…, 최소치)`가 두 방식 중 **하나라도** 참이면 계산한다.
- 이 기준은 가게·장소의 캠퍼스 값에 기대므로, 가게 크론(19:00 UTC)과 구간 크론(19:30 UTC)이 끝난 뒤 돌아야 한다.
- 크론 경로: `/api/cron/walk-legs`가 `refreshLegs()` 다음에 `refreshPlaceLegs()`를 부르고 두 보고를 합쳐 돌려준다. Vercel 크론을 늘리지 않으려고 따로 만들지 않는다.
- TMAP 초당 제한을 모르니 지금처럼 하나씩 순서대로 부른다. 산책 구간 21건 + 가게 구간 약 46건이라 함수 시간 안에 든다.

### 4-3. 포장 가능한 가게

다음 중 하나면 포장해서 먹기에 쓴다.
- 카테고리가 **패스트푸드** 또는 **분식** (햄버거, 김밥처럼 들고 가서 먹기 좋은 것)
- `places.preorder = true`
- 키워드 "🥡 포장 OK"(`takeout`)를 1명 이상 골랐음

2026-10-23 운영 데이터로는 **맥도날드 서초GS점, 왓더버거, 김밥천국** 세 곳이다. 사용자가 든 예와 같다.
카테고리 목록은 `domain.ts`에 `TAKEOUT_CATEGORIES = ["패스트푸드", "분식"]`으로 둔다. 다른 카테고리 가게는 키워드로 들어온다.

### 4-4. API

- `GET /api/walk` 응답에 `placeLegs: PlaceLeg[]`를 더한다(`readPlaceLegs()`, 경로 좌표 제외). 점심 코스 계산에 필요한 나머지(가게, 장소, 구간)는 이미 화면에 있다.
- `GET /api/walk/lunch-path?place=<id>&spot=<id>&mode=dine|takeout` 는 지도에 그릴 세 구간의 좌표를 돌려준다: `{ legs: [{ path }, { path }, { path }] }`.
  - **캠퍼스 → 가게:** `readPlacePath`
  - **가게 → 장소:** `readPlaceLegPath`. 없으면 null
  - **장소 → 캠퍼스:** `walk_legs` 캠퍼스 구간을 뒤집은 것
- 가게 응답(`GET /api/places`)에 `preorder`를 더한다. `Place` 타입에도 더한다.
- 산책 장소 응답에 `picnic`을 더한다. `WalkSpot` 타입에도 더한다.

### 7-1. 순수 함수 (`lunchCourses`, `placeLegBounds`)

가게·장소 값을 직접 넣어 확인한다. 아래는 손으로 계산한 기댓값이다.

| 경우 | c→p | c→s | p→s | 둘러보기/먹기 | 기대 |
|---|---|---|---|---|---|
| 먹고 걷기, TMAP 없음(크론 전), 최대치로 통과 | 3분 | 8분 | 없음 (최대 11) | 10 | 된다. 11+10+8 = 29 ≤ 30 |
| 먹고 걷기, 최소치로도 넘침 | 4분 | 23분 | 없음 (최소 19) | 3 | 안 된다. 19+3+23 = 45 |
| 먹고 걷기, 최대치로는 넘침·TMAP 없음(크론 전) | 7분 | 15분 | 없음 (8~22) | 5 | 안 된다 |
| 먹고 걷기, 같은 쌍·TMAP 있음 | 7분 | 15분 | 9분 | 5 | 된다. 9+5+15 = 29 |
| 포장, 미리 주문 | 4분 | 12.8분 | 9.6분 | 20 | 된다. 4+2+9.6+20+12.8 = 48.4 → 48분, 13:38 복귀 |
| 포장, `picnic = false` 장소 | 아무 값 | | | | 목록에 없음 |
| 지금 13:30, 포장, 합계 48분 | | | | | 14:18 → 목록에 없음 |
